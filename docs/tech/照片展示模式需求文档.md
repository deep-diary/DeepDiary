# 照片展示模式需求文档

## 1. 需求概述

在 Web 聊天页面中，系统需要支持三种显示模式，根据不同的场景自动切换：
1. **聊天模式**：左侧聊天框，右侧使用 iframe 调用 Immich Kiosk 轮播对应人物的照片
2. **全屏轮播模式**：一段时间没有聊天后，自动切换到全屏轮播模式，展示最后识别到的人物的照片（如果没有人物，则轮播所有照片）
3. **自然语言搜索模式**：左侧聊天框，右侧使用 gallery 组件显示自然语言搜索结果的6张图片

## 2. 功能需求

### 2.1 三种显示模式

#### 模式 A：聊天模式（默认模式）

- **布局**：左侧聊天框，右侧 iframe 轮播
- **触发条件**：
  - 页面初始加载
  - 从全屏轮播模式切换回来
  - 收到新的聊天消息
- **右侧 iframe 行为**：
  - 当声纹识别或人脸识别到人物时，更新 iframe 的 URL，轮播该人物的照片
  - URL 格式：`{kiosk_url}/?person={person_id}`（使用人物 ID）
  - 如果识别到新人物，自动更新 iframe URL 切换到新人物
- **显示内容**：
  - 左侧：聊天记录、消息输入框
  - 右侧：Immich Kiosk iframe（轮播当前识别到的人物照片）

#### 模式 B：全屏轮播模式

- **布局**：全屏显示，隐藏其他所有组件（除了 iframe）
- **触发条件**：
  - 从聊天模式自动切换：距离最后一次聊天消息或人物更新已超过 **20 秒**（可配置阈值）
  - 已识别到人物（`person_name` 不为空）
- **显示内容**：
  - 全屏 iframe，轮播最后识别到的人物的照片
  - 如果没有识别到任何人物，则不加人物参数，默认轮播 Immich 服务器的所有照片
- **退出条件**：
  - 收到新的 WebSocket 消息（任何类型的消息）
  - 用户主动发送聊天消息
  - 识别到新的人物（人物名称发生变化）

#### 模式 C：自然语言搜索模式

- **布局**：左侧聊天框，右侧 gallery 组件显示6张图片
- **触发条件**：
  - 用户通过自然语言搜索照片（例如："找一张在海边的照片"）
  - 服务端返回 `IMMICH_SEARCH_RESULT` 消息，且包含 `query` 参数（非空）
- **显示内容**：
  - 左侧：聊天记录、消息输入框
  - 右侧：gallery 组件，显示搜索结果的6张图片（固定显示相似度最高的6张，如果服务器返回少于6张，则按实际数量显示）
- **退出条件**：
  - 切换到其他模式（聊天模式或全屏轮播模式）
  - 新的搜索请求（会更新 gallery 内容）
  - **注意**：如果空闲20秒，会自动切换到全屏轮播模式（优先级高于搜索模式）

### 2.2 人物识别与跟踪

- **触发条件**：服务端通过人脸识别或声纹识别识别到人物
- **数据来源**：
  - WebSocket 消息中的 `person_name` 字段（来自服务端的人脸识别和声纹识别）
  - WebSocket 消息中的 `IMMICH_KIOSK_URL` 消息类型（包含 kiosk_url 和 person_name）
- **状态记录**：在 `chat_page` 中记录并保持最后一次识别到的人物信息
- **URL 更新**：当识别到人物时，更新右侧 iframe 的 URL，切换到该人物的照片轮播

### 2.3 自动切换逻辑

- **从聊天模式切换到全屏轮播模式的条件**：
  - 距离最后一次聊天消息或人物更新已超过 **20 秒**（可配置阈值）
  - **注意**：无论当前在什么模式（包括自然语言搜索模式），只要空闲20秒，都会切换到全屏轮播模式
- **从全屏轮播模式切换回聊天模式的条件**：
  - 收到新的 WebSocket 消息（任何类型的消息）
  - 用户主动发送聊天消息
  - 识别到新的人物（人物名称发生变化）

### 2.4 页面切换机制

- **切换方式**：在同一页面内使用 `gr.Column` 的 `visible` 属性控制显示/隐藏
- **切换时机**：
  - 满足条件时自动切换到全屏轮播模式
  - 有新消息时自动切换回聊天模式
- **用户体验**：
  - 切换应平滑，无闪烁
  - 切换时保持 WebSocket 连接状态
  - 切换时保持聊天历史记录

```python
@staticmethod
def build_immich_kiosk_url_message(
    kiosk_url: str,
    person_name: Optional[str] = None,
    person_id: Optional[str] = None,
    device_id: str
) -> Dict[str, Any]:
    """构建 Immich Kiosk URL 消息（服务器 → Web客户端）
    
    Args:
        kiosk_url: Immich Kiosk 完整 URL（包含参数）
        person_name: 人物名称（可选）
        person_id: 人物 ID（可选）
        device_id: 设备ID
        
    Returns:
        Dict: Immich Kiosk URL 消息字典
    """
    message = {
        "type": WebMessageType.IMMICH_KIOSK_URL.value,
        "data": {
            "kiosk_url": kiosk_url,
            "device_id": device_id
        },
        "device_id": device_id
    }
    if person_name:
        message["data"]["person_name"] = person_name
    if person_id:
        message["data"]["person_id"] = person_id
    return message
```

#### 3.2.3 ASR Base 修改

在 `core/providers/asr/base.py` 中修改声纹识别逻辑：

**修改前**（第192-204行）：
- 识别到人物后，调用 `search_and_send_person_photos` 函数
- 该函数会搜索人物照片并发送 `IMMICH_SEARCH_RESULT` 消息

**修改后**：
- 识别到人物后，直接构建并发送 `IMMICH_KIOSK_URL` 消息
- 从配置中读取 `kiosk_url`（来自 `.config.yaml` 的 `Immich.kiosk_url`）
- 构建 URL：`{kiosk_url}/?people={person_id}` 或 `{kiosk_url}/?person={person_name}`
- 发送消息到前端

**实现示例**：
```python
# 识别到有效声纹后，发送 Kiosk URL 给前端
if speaker_name and speaker_name != "未知说话人":
    if hasattr(conn, 'server') and conn.server and hasattr(conn.server, 'forward_to_web_by_device_id'):
        # 获取 Immich 配置
        immich_config = conn.config.get("Immich", {})
        kiosk_base_url = immich_config.get("kiosk_url", "")
        
        if kiosk_base_url:
            from core.protocol.message_builder import WebMessageBuilder
            
            # 异步获取人物 ID（不阻塞主流程）
            async def get_person_id_and_send():
                try:
                    # 获取 ImmichLogic 实例
                    immich_logic = conn.get_immich_logic()
                    if immich_logic:
                        # 搜索人物，获取 person_id
                        person_info = await immich_logic.api.get_person_by_name(speaker_name)
                        person_id = person_info.get("id") if person_info else None
                    else:
                        person_id = None
                    
                    # 构建 URL（使用 person_id，如果没有则使用 person_name）
                    if person_id:
                        kiosk_url = f"{kiosk_base_url.rstrip('/')}/?person={person_id}"
                    else:
                        # 降级方案：使用 person_name（但 Kiosk 可能需要 person_id）
                        kiosk_url = f"{kiosk_base_url.rstrip('/')}/?person={speaker_name}"
                    
                    # 构建并发送消息
                    message = WebMessageBuilder.build_immich_kiosk_url_message(
                        kiosk_url=kiosk_url,
                        person_name=speaker_name,
                        person_id=person_id,
                        device_id=conn.device_id
                    )
                    
                    await conn.server.forward_to_web_by_device_id(conn.device_id, message)
                    logger.bind(tag=TAG).info(f"已发送 Kiosk URL 到前端: {kiosk_url}, person_id={person_id}")
                except Exception as e:
                    logger.bind(tag=TAG).error(f"获取人物ID并发送Kiosk URL失败: {e}", exc_info=True)
            
            # 异步执行，不阻塞主流程
            asyncio.create_task(get_person_id_and_send())
        else:
            logger.bind(tag=TAG).warning("Immich Kiosk URL 未配置")
    else:
        logger.bind(tag=TAG).warning("无法发送 Kiosk URL: server或forward_to_web_by_device_id方法不存在")
```

**注意**：后端获取 person_id 的效率更高，且不阻塞主流程（使用异步任务）。

#### 3.3.6 空闲检测与自动切换

在 `chat_page.py` 中实现空闲检测：

```python
def check_and_switch_mode(self) -> tuple:
    """检查并切换模式"""
    # 如果当前在自然语言搜索模式，不自动切换
    if self.chat_service.get_current_mode() == "search":
        return self._no_change()
    
    # 如果当前在全屏轮播模式，检查是否有新消息
    if self.chat_service.get_current_mode() == "slideshow":
        if self.chat_service.should_exit_slideshow():
            return self.switch_to_chat_mode()
        return self._no_change()
    
    # 如果当前在聊天模式，检查是否应该切换到全屏轮播
    if self.chat_service.should_enter_slideshow():
        return self.switch_to_slideshow_mode()
    
    return self._no_change()
```

### 3.4 Immich Kiosk URL 格式

根据 Immich Kiosk 文档和用户确认，URL 格式如下：

- **使用人物 ID**：`{kiosk_url}/?person={person_id}`（推荐，更准确）
- **使用人物名称**：`{kiosk_url}/?person={person_name}`（降级方案，如果无法获取 person_id）
- **无参数**：`{kiosk_url}`（显示所有照片，用于全屏轮播模式且没有识别到人物时）

**配置来源**：
- 后端配置：`.config.yaml` 中的 `Immich.kiosk_url`
- 前端配置：`config.json` 中的 `immich.kiosk_url`（可选，用于前端默认值）

#### iframe 嵌入代码

```python
def _build_iframe_html(self, kiosk_url: Optional[str] = None) -> str:
    """构建 iframe HTML"""
    if not kiosk_url:
        # 使用默认 URL
        kiosk_url = self.kiosk_base_url
    
    html_content = f"""
    <div style="width: 100%; height: 100vh; margin: 0; padding: 0; overflow: hidden;">
    <iframe
```

## 6. 注意事项

1. **WebSocket 连接**：切换模式时保持 WebSocket 连接不断开
2. **状态保持**：切换模式时保持聊天历史记录和人物信息
3. **性能考虑**：
   - 定时器检查频率不宜过高（建议 1 秒），避免性能问题
   - iframe 加载可能较慢，需要适当的加载提示
4. **用户体验**：
   - 切换应平滑，避免闪烁
   - 全屏轮播模式应隐藏所有其他 UI 元素，提供沉浸式体验
5. **错误处理**：
   - 如果 Immich Kiosk 加载失败，应回退到聊天模式
   - 如果 Kiosk URL 未配置，应显示提示信息
6. **人物参数格式**：
   - 优先使用 `person_id`（更准确）
   - 如果没有 `person_id`，使用 `person_name` 作为降级方案
   - URL 参数格式：`?person={person_id}` 或 `?person={person_name}`
   - 后端异步获取 `person_id`，不阻塞主流程
7. **模式切换优先级**：
   - 自然语言搜索模式优先级最高（用户主动搜索，立即切换）
   - 但无论当前在什么模式，如果空闲20秒，都会自动切换到全屏轮播模式
   - 聊天模式为默认模式
8. **消息处理顺序**：
   - 先处理 `IMMICH_KIOSK_URL` 消息（更新 iframe）
   - 再处理 `IMMICH_SEARCH_RESULT` 消息（判断是否为自然语言搜索）
   - 最后处理其他消息（可能触发模式切换）
