# 照片展示模式需求文档

## 1. 需求概述

在 Web 聊天页面中，当识别到人物后，如果一段时间内没有新的聊天消息，系统应自动切换到照片展示模式，以沉浸式的方式展示该人物的照片轮播。

## 2. 功能需求

### 2.1 人物识别与跟踪

- **触发条件**：服务端通过人脸识别或声纹识别识别到人物
- **数据来源**：WebSocket 消息中的 `person_name` 字段（来自服务端的人脸识别和声纹识别）
- **状态记录**：在 `chat_page` 中记录并保持最后一次识别到的人物信息
- **显示位置**：在 `gallery` 组件下方显示当前识别到的人物姓名

### 2.2 自动切换逻辑

- **进入照片展示模式的条件**：
  - 已识别到人物（`person_name` 不为空）
  - 距离最后一次聊天消息或人物更新已超过 **20 秒**（可配置阈值）
  - 没有其他新的查询请求
- **退出照片展示模式的条件**：
  - 收到新的 WebSocket 消息（任何类型的消息）
  - 用户主动发送聊天消息
  - 识别到新的人物（人物名称发生变化）

### 2.3 照片展示页面（frame_page）

- **页面类型**：新的 Gradio Tab 页面，命名为 "📸 照片展示"
- **实现方式**：使用 `gr.HTML` 组件嵌入 `iframe`，加载 Immich Kiosk 应用
- **URL 参数传递**：
  - 通过 URL 参数传递人物姓名：`https://demo.immichkiosk.app/?person=人物姓名`
  - 或使用 Immich Kiosk 的 API 参数格式（需查阅文档）
- **页面切换**：
  - 自动从 `chat_page` 切换到 `frame_page`
  - 自动从 `frame_page` 切换回 `chat_page`

### 2.4 页面切换机制

- **切换方式**：程序化切换 Gradio Tab
- **切换时机**：
  - 满足条件时自动切换到 `frame_page`
  - 有新消息时自动切换回 `chat_page`
- **用户体验**：
  - 切换应平滑，无闪烁
  - 切换时保持 WebSocket 连接状态
  - 切换时保持聊天历史记录

### 3.2 核心组件

#### 3.2.1 ChatService 增强

- **新增属性**：

  - `last_person_name: Optional[str]` - 最后一次识别到的人物名称
  - `last_message_time: float` - 最后一次消息的时间戳
  - `idle_timer: Optional[threading.Timer]` - 空闲定时器

- **新增方法**：
  - `update_person_name(person_name: str)` - 更新人物名称并重置定时器
  - `reset_idle_timer()` - 重置空闲定时器
  - `should_enter_slideshow() -> bool` - 判断是否应该进入照片展示模式
  - `get_last_person_name() -> Optional[str]` - 获取最后识别到的人物名称

#### 3.2.2 ChatPage 增强

- **新增属性**：

  - `idle_check_interval: float = 1.0` - 空闲检查间隔（秒）
  - `idle_threshold: float = 20.0` - 空闲阈值（秒）
  - `current_tab: str = "chat"` - 当前 Tab 标识

- **新增方法**：
  - `check_and_switch_to_slideshow()` - 检查并切换到照片展示模式
  - `switch_to_chat_page()` - 切换回聊天页面
  - `on_new_message()` - 新消息回调（重置定时器）

#### 3.2.3 FramePage（新建）

- **职责**：照片展示页面，嵌入 Immich Kiosk
- **组件**：

  - `gr.HTML` 组件，包含 iframe
  - 动态生成 iframe URL（包含人物参数）

- **方法**：
  - `build() -> gr.Column` - 构建页面 UI
  - `update_person(person_name: str)` - 更新显示的人物

#### 3.2.4 UIManager 增强

- **新增属性**：

  - `_frame_page: Optional[FramePage]` - 照片展示页面实例
  - `_tabs: Optional[gr.Tabs]` - Tabs 组件引用（用于切换）

- **修改方法**：
  - `build()` - 添加 `frame_page` Tab
  - 提供页面切换接口给 `ChatPage`

### 3.3 页面切换实现

#### 方案 A：使用 Gradio 的 JavaScript API（推荐）

```python
# 在 ChatPage 中
def switch_to_frame_page(self):
    """切换到照片展示页面"""
    # 使用 JavaScript 切换 Tab
    return gr.update(selected=1)  # 假设 frame_page 是第 2 个 Tab

def switch_to_chat_page(self):
    """切换回聊天页面"""
    return gr.update(selected=0)  # chat_page 是第 1 个 Tab
```

```python
# 在 ChatPage.build() 中
```

#### 方案 C：使用事件驱动的切换（最佳）

```python
# 在 ChatPage 中监听 WebSocket 消息
def _on_websocket_message(self, message):
    # 处理消息
    self.on_new_message()  # 重置定时器

        self.switch_to_chat_page()
```

## 6. 注意事项

1. **WebSocket 连接**：切换页面时保持 WebSocket 连接不断开
2. **状态保持**：切换页面时保持聊天历史记录和人物信息
3. **性能考虑**：定时器检查频率不宜过高，避免性能问题
4. **用户体验**：切换应平滑，避免闪烁
5. **错误处理**：如果 Immich Kiosk 加载失败，应回退到聊天页面
6. **人物参数格式**：需确认 Immich Kiosk 支持的人物参数格式（姓名还是 ID）

## 7. 方案评估与对比

### 7.1 方案对比

#### 方案 A：Gradio Tab 切换（原方案）

**实现方式**：创建新的 Tab 页面，使用 `gr.Tabs()` 和 `gr.TabItem()` 组织，通过 JavaScript 或事件切换 Tab。

**优点**：

- ✅ 实现简单，符合 Gradio 的设计模式
- ✅ 代码结构清晰，页面分离
- ✅ 易于维护和扩展

**缺点**：

- ❌ Tab 栏会占用屏幕空间
- ❌ 切换时可能不够平滑
- ❌ 用户可能看到 Tab 栏，影响沉浸感
- ❌ 需要管理多个 Tab 的状态

**适用场景**：需要多个独立功能页面的场景。

---

#### 方案 B：同一页面内视图切换（推荐 ⭐）

**实现方式**：在 `chat_page` 内使用两个 `gr.Column`，通过 `visible` 属性控制显示/隐藏，实现视图切换。

**优点**：

- ✅ **沉浸式体验**：无 Tab 栏，全屏展示
- ✅ **平滑切换**：使用 `gr.update(visible=True/False)` 实现平滑过渡
- ✅ **状态保持**：在同一页面内，状态更容易保持
- ✅ **用户体验好**：切换更自然，无页面跳转感
- ✅ **实现简单**：只需控制 `visible` 属性

**缺点**：

- ⚠️ 需要在同一页面内管理两个视图
- ⚠️ 页面代码可能稍显复杂

**实现示例**：

```python
with gr.Column(visible=True) as chat_view:
    # 聊天界面组件
    chatbot = gr.Chatbot(...)
    gallery = gr.Gallery(...)

with gr.Column(visible=False) as slideshow_view:
    # 照片展示界面组件
    kiosk_html = gr.HTML(...)

# 切换函数
def switch_to_slideshow():
    return (
        gr.update(visible=False),  # chat_view
        gr.update(visible=True)     # slideshow_view
    )
```

**适用场景**：需要沉浸式体验的场景，如照片展示、全屏视频等。

---

#### 方案 C：使用 gr.Blocks 的 load 事件

**实现方式**：使用 Gradio 的 `load` 事件和自定义 JavaScript 实现页面跳转。

**优点**：

- ✅ 可以实现复杂的页面跳转逻辑

**缺点**：

- ❌ 需要编写 JavaScript 代码
- ❌ 复杂度高，维护成本高
- ❌ 不符合 Gradio 的设计理念

**适用场景**：需要复杂页面跳转逻辑的场景。

---

#### 方案 D：混合方案（最佳实践 ⭐）

**实现方式**：结合方案 B，但在 `UIManager` 中仍然创建独立的 `FramePage` 类，然后在 `chat_page` 中嵌入照片展示视图。

**优点**：

- ✅ **代码组织清晰**：`FramePage` 独立管理照片展示逻辑
- ✅ **用户体验好**：在同一页面内切换，无 Tab 栏
- ✅ **易于维护**：职责分离，便于测试和扩展
- ✅ **灵活性高**：可以轻松切换回 Tab 模式

**架构设计**：

```
ChatPage
├── chat_view (Column, visible=True)
│   ├── Chatbot
│   ├── Gallery
│   └── 其他聊天组件
└── slideshow_view (Column, visible=False)
    └── FramePage.build()  # 嵌入照片展示组件
```

**适用场景**：需要代码组织和用户体验兼顾的场景。

---

### 7.2 推荐方案

**推荐使用方案 D（混合方案）**，原因：

1. **用户体验优先**：在同一页面内切换，无 Tab 栏，沉浸式体验
2. **代码组织清晰**：`FramePage` 独立管理照片展示逻辑，职责分离
3. **易于维护**：各组件独立，便于测试和扩展
4. **灵活性高**：可以轻松切换实现方式

### 7.3 实现细节

#### 7.3.1 ChatPage 结构

```python
class ChatPage:
    def build(self):
        with gr.Row():
            # 聊天视图
            with gr.Column(visible=True) as self.chat_view:
                # 现有的聊天界面组件
                self.chatbot = gr.Chatbot(...)
                self.person_gallery = gr.Gallery(...)
                # ...

            # 照片展示视图
            with gr.Column(visible=False) as self.slideshow_view:
                # 嵌入 FramePage
                self.frame_page = FramePage(...)
                self.frame_page_html = self.frame_page.build()

        # 返回两个视图的引用，用于切换
        return self.chat_view, self.slideshow_view
```

#### 7.3.2 切换逻辑

```python
def switch_to_slideshow(self, person_name: str):
    """切换到照片展示模式"""
    # 更新 iframe URL
    kiosk_url = f"https://demo.immichkiosk.app/?person={person_name}"
    html_content = f'<iframe src="{kiosk_url}" width="100%" height="100vh" frameborder="0"></iframe>'

    return (
        gr.update(visible=False),  # chat_view
        gr.update(visible=True),   # slideshow_view
        gr.update(value=html_content)  # frame_page_html
    )

def switch_to_chat(self):
    """切换回聊天页面"""
    return (
        gr.update(visible=True),   # chat_view
        gr.update(visible=False)   # slideshow_view
    )
```

#### 7.3.3 定时检查

```python
# 使用 gr.Timer 定期检查
idle_timer = gr.Timer(value=1.0, active=True)
idle_timer.tick(
    fn=self.check_and_switch,
    inputs=[self.chatbot],  # 监听聊天历史
    outputs=[self.chat_view, self.slideshow_view, self.frame_page_html]
)
```
